# Triage（分类）

在 issue 追踪器上将 issues 移动通过一个由分类角色组成的小型状态机。

在分类期间发布到 issue 追踪器的每条评论或 issue **必须**以以下免责声明开头：

```
> *This was generated by AI during triage.*
```

## Reference docs（参考文档）

- [AGENT-BRIEF.md](AGENT-BRIEF.md) — 如何编写持久的 agent brief
- [OUT-OF-SCOPE.md](OUT-OF-SCOPE.md) — `.out-of-scope/` 知识库的工作原理

## Roles（角色）

两个**类别**角色：

- `bug` — 某些东西坏了
- `enhancement` — 新功能或改进

五个**状态**角色：

- `needs-triage` — 维护者需要评估
- `needs-info` — 等待报告者提供更多信息
- `ready-for-agent` — 完全指定，准备好供 AFK agent 处理
- `ready-for-human` — 需要人类实现
- `wontfix` — 不会处理

每个被分类的 issue 应该恰好携带一个类别角色和一个状态角色。如果状态角色冲突，标记出来并在执行任何其他操作之前询问维护者。

这些是规范的角色名称——issue 追踪器中实际使用的标签字符串可能不同。映射应该已经提供给你——如果没有，运行 `/setup-matt-pocock-skills`。

状态转换：未标记的 issue 通常首先进入 `needs-triage`；从那里它可以移动到 `needs-info`、`ready-for-agent`、`ready-for-human` 或 `wontfix`。`needs-info` 在报告者回复后返回 `needs-triage`。维护者可以随时覆盖——标记看起来不寻常的转换并在继续前询问。

## Invocation（调用）

维护者调用 `/triage` 并用自然语言描述他们想要什么。解释请求并执行。示例：

- "Show me anything that needs my attention"（给我看任何需要我关注的东西）
- "Let's look at #42"（让我们看看 #42）
- "Move #42 to ready-for-agent"（将 #42 移动到 ready-for-agent）
- "What's ready for agents to pick up?"（有什么准备好让 agent 接手了？）

## Show what needs attention（展示需要关注的内容）

查询 issue 追踪器并展示三个桶，从最旧的开始：

1. **Unlabeled**（未标记）— 从未被分类过。
2. **`needs-triage`** — 评估进行中。
3. **`needs-info` with reporter activity since the last triage notes**（自上次分类笔记以来有报告者活动的 `needs-info`）— 需要重新评估。

展示计数和每个 issue 的单行摘要。让维护者选择。

## Triage a specific issue（分类特定 issue）

1. **Gather context（收集上下文）。** 阅读完整的 issue（正文、评论、标签、报告者、日期）。解析任何先前的分类笔记，这样你就不会重复问已解决的问题。使用项目的领域词汇表探索代码库，尊重该区域的 ADR。阅读 `.out-of-scope/*.md` 并展示任何与此 issue 相似的先前拒绝。

2. **Recommend（推荐）。** 告诉维护者你的类别和状态推荐及理由，加上与 issue 相关的代码库简要摘要。等待指示。

3. **Reproduce (bugs only)（复现）（仅限 Bug）。** 在任何 grilling 之前，尝试复现：阅读报告者的步骤，追踪相关代码，运行测试或命令。报告发生了什么——成功复现并附带代码路径、失败复现，或细节不足（强烈的 `needs-info` 信号）。确认的复现会产生更强大的 agent brief。

4. **Grill (if needed)（追问）（如果需要）。** 如果 issue 需要充实，运行 `/grill-with-docs` 会话。

5. **Apply the outcome（应用结果）：**
   - `ready-for-agent` — 发布 agent brief 评论（[AGENT-BRIEF.md](AGENT-BRIEF.md)）。
   - `ready-for-human` — 与 agent brief 结构相同，但注明为什么不能委派（判断调用、外部访问、设计决策、手动测试）。
   - `needs-info` — 发布分类笔记（模板如下）。
   - `wontfix` (bug) — 礼貌解释，然后关闭。
   - `wontfix` (enhancement) — 写入 `.out-of-scope/`，从评论链接到它，然后关闭（[OUT-OF-SCOPE.md](OUT-OF-SCOPE.md)）。
   - `needs-triage` — 应用角色。如果有部分进展，可选评论。

## Quick state override（快速状态覆盖）

如果维护者说"将 #42 移动到 ready-for-agent"，信任他们并直接应用角色。确认你将要做什么（角色变更、评论、关闭），然后执行。跳过 grilling。如果在没有 grilling 会话的情况下移动到 `ready-for-agent`，询问他们是否想写 agent brief。

## Needs-info template（Needs-info 模板）

```markdown
## Triage Notes（分类笔记）

**What we've established so far（目前已确定的）：**

- point 1
- point 2

**What we still need from you (@reporter)（我们还需要你提供的）：**

- question 1
- question 2
```

在"established so far"下捕获 grilling 期间解决的所有内容，这样工作不会丢失。问题必须具体且可操作，而非"请提供更多信息"。

## Resuming a previous session（恢复之前的会话）

如果 issue 上存在先前的分类笔记，阅读它们，检查报告者是否回答了任何未解决的问题，并在继续之前展示更新的情况。不要重复问已解决的问题。
